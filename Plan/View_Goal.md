# View层（界面层）功能需求规格说明

> 本说明文档依据《2025面向对象程序设计训练》大作业**第 2 章“软件基本功能要求”** 及 **第 3 章“设计与实现要求”** 中关于界面层（View层）的职责与约束整理。  
> **界面层定位**：开发环境提供的、与图形/非图形交互界面相关的类（MVC模式中的V）。本说明文档仅陈述界面层**必须完成的交互与显示任务**，具体类设计或内部实现细节需要在设计文档中落实。

## 1. 界面层总体定位与职责

- **交互入口**：界面层是用户与系统交互的唯一入口，负责接收用户的所有操作指令（命令、参数、文件路径等）。
- **数据呈现**：界面层负责将业务层（Controller层）返回的数据结果以人类可读的形式（字符表格、列表、提示信息等）展示给用户。
- **零业务逻辑**：界面层**不得包含任何业务逻辑**（如验证依赖图是否有环、计算关键路径等），所有功能性请求必须委托给业务层处理。界面层仅负责“翻译”用户操作为对业务层的调用，并将业务层的响应“渲染”为输出。
- **输入校验（基础格式）** ：界面层可对用户输入进行**格式层面**的初步检查（如数字是否合法、名称是否为空），但深度的业务约束校验（如名称唯一性、DAG约束）应由业务层负责。

## 2. 界面层必须支持的操作命令（功能入口）

界面层需向用户提供以下全部功能的触发入口（无论采用命令行菜单、图形界面按钮或指令交互形式）：

### 2.1 项目文件操作

- **导入项目**：接收用户输入的**文件路径**，触发业务层的导入功能，并反馈导入结果（成功/失败及失败原因）。
- **导出项目**：接收用户输入的**文件路径**，触发业务层的导出功能，并反馈导出结果。

### 2.2 任务（Task）管理

- **列出所有任务**：触发“列出任务”功能，并**显示**业务层返回的每个任务的：
  - 容器索引（序号）
  - 名称
  - 工期
  - 前置任务列表
  - 后继任务列表
  显示格式（表格、列表等）由界面层自行拟定。
- **删除任务**：接收用户指定的**容器索引**，触发删除操作，并反馈执行结果（成功/失败）。
- **添加任务**：接收用户输入的**名称**和**工期**，触发添加操作，并反馈执行结果（含自动类型转换提示，如是否自动创建为里程碑）。
- **查询前驱/后继**：接收用户指定的**容器索引**，触发查询操作，并**显示**该任务的：
  - 所有前驱任务（Predecessors）的容器索引和名称
  - 所有后继任务（Successors）的容器索引和名称
- **修改任务**：接收用户指定的**容器索引**、**新名称**和/或**新工期**，触发修改操作，并反馈执行结果（含自动类型转换提示）。

### 2.3 依赖（Dependency）管理

- **列出所有依赖**：触发“列出依赖”功能，并**显示**每个依赖的：
  - 序号
  - 前置任务的容器索引
  - 后置任务的容器索引
  - 依赖类型（Type）
- **删除依赖**：接收用户指定的**容器索引**或**前置任务+后置任务信息**，触发删除操作，并反馈执行结果。
- **添加依赖**：接收用户输入的**前置任务、后置任务、依赖类型（FS/SS/FF/SF）和 Lag 值**，触发添加操作，并反馈执行结果（若违反DAG约束需向用户明确提示拒绝原因）。

### 2.4 资源（Resource）管理

- **列出所有资源**：触发“列出资源”功能，并**显示**每个资源的：
  - 容器索引
  - 名称
  - 单位成本
- **添加资源**：接收用户输入的**名称**和**单位成本**，触发添加操作，并反馈执行结果（名称重复时需明确提示）。
- **为任务分配资源**：接收用户输入的**任务序号**和**资源序号**（以及可选的数量，PPM格式中含数量字段），触发分配操作，并反馈执行结果。

### 2.5 统计信息展示

- **显示统计信息**：触发“统计”功能，并**显示**业务层返回的：
  - Task总数
  - Dependency总数
  - Resource总数
  - 当前项目的总工期（关键路径长度，单位：天）

### 2.6 项目验证与调度计算

- **执行项目验证**：触发“合理性验证”功能，并**清晰展示**验证结果：
  - 若合理（IsValid == true），给出明确通过提示。
  - 若不合理（IsValid == false），**必须明确列出**未通过的具体项（如环路涉及的ID、悬挂节点ID、缺失引用ID等）。
- **执行调度计算**：触发“关键路径调度计算”功能（通常仅在项目合理时启用），并**显示**业务层返回的：
  1. 项目的总工期。
  2. 位于关键路径上的所有任务ID列表（按拓扑顺序）或任务名称列表。

## 3. 界面层的开发与实现约束

根据大作业第3章要求，界面层（View层）受到以下**强制性约束**：

- **必须为类形式**：界面层必须以**类的形式**存在，不可直接写在 `main` 函数或其他非类成员的函数中。`main` 函数仅应负责实例化界面类并启动其运行。
- **自动生成代码许可**：界面层是**唯一**允许使用开发环境（如Qt Designer、Visual Studio Designer）自动生成代码框架的层级。自动生成的代码仅可做少量注释。
- **数据类型特例（宽松）** ：界面层及业务流程/控制器层可以使用开发环境提供的特定数据类型（如Qt的 `QString`、`QList` 等）进行参数传递，但这些数据类型**不得传入**可重用模型类（Model层）中。
- **非交互限制**：界面层不限于图形界面（GUI）或命令行界面（CLI）。明确指出：**图形界面不加分，非图形界面不减分**，实现方式由开发者自行选择。
- **零业务逻辑**：界面层代码中必须避免实现业务规则（如计算ES/EF、检查DAG等），仅负责调用Controller层对应方法并处理显示逻辑。

## 4. 界面层显示格式要求（自由度说明）

大作业多处明确“显示格式自拟”（如2.3.1、2.3.4等），这意味着：

- 界面层设计者可根据所选界面类型（命令行表格、树形结构、图形表格控件等）自由决定数据的**视觉排版方式**。
- **唯一硬性要求**：所显示的信息字段**必须完整且无歧义**（例如，列出任务时必须同时展示序号、名称、工期、前置列表、后继列表，不可遗漏）。
- 所有错误、警告和操作反馈信息（如“删除成功”、“名称已存在”、“依赖图将产生环路，操作被拒绝”）必须以友好的提示形式呈现给用户，避免直接抛出堆栈跟踪或原始异常码（除非异常不可恢复）。
