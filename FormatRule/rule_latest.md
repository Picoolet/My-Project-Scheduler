# OOP 课程代码规范 (C++) - 项目规则

本规范为强制性编码标准，所有代码必须完全遵守。  
规则检查分工：

- 标记为 `[clang-format]` 的规则已由项目根目录下的 `.clang-format` 配置文件自动检查和格式化，无需额外人工关注。
- 标记为 `[agent]` 的规则由 coding agent 负责审查，格式工具无法保证其正确性。
- 标记为 `[agent + clang-format]` 的规则，语义正确性由 agent 保证，具体格式由 clang-format 自动修正。

---

## 1. 格式

### 1.1 空行 `[agent]`

- 在 `.hpp` 和 `.cpp` 文件中，各主要部分（文件头注释、`#include`、`#define`、类型声明、实现等）之间必须用空行隔开。
- 一个函数内部，完成不同功能的段落之间必须用空行隔开。

### 1.2 必须使用空格的位置 `[clang-format]`

- 二元操作符（赋值、关系、逻辑、位、算术等）两边各加一个空格。
- 三目运算符 `?` 和 `:` 前后各加一个空格。
- 函数参数列表、初始化列表、枚举定义、模板参数中的逗号后必须加一个空格（可多个空格用于对齐）。
- 控制语句 (`if`, `for`, `while`, `switch`) 和其后的 `(` 之间加一个空格。
- 控制语句后的 `)` 与 `{` 之间加一个空格（当 `{` 在同一行时，本规范中 `{` 总是另起一行，因此此条自动满足）。
- `do` 和其后的 `{` 之间加一个空格（`{` 另起一行时同样满足）。
- `case` 和 `default` 标签后的 `:` 前后各加一个空格。

### 1.3 禁止使用空格的位置 `[clang-format]`

- 成员访问操作符 `.` 和 `->`、下标操作符 `[]` 前后不加空格。
- 作用域解析操作符 `::` 前后不加空格。
- 一元操作符 (`++`, `--`, `!`, `&`, `*` 等) 与操作数之间不加空格。
- 分号 `;` 之前不能有空格。

### 1.4 多空格对齐 `[clang-format]`

- 当连续多行声明变量或进行相似赋值时，必须使用空格使变量名、等号、初始值等元素在列上对齐（clang-format 自动完成）。

### 1.5 缩进 `[clang-format]`

- 使用 4 个空格作为一个缩进单位，严格按逻辑控制层次缩进。

### 1.6 控制语句必须使用大括号 `[agent + clang-format]`

- `if`, `for`, `while`, `do...while`, `switch` 的语句体必须用 `{` 和 `}` 括起来，即使只有一条语句。**（由 agent 保证大括号一定存在）**
- `{` 必须单独占一行，并与控制语句的首字母对齐。（clang-format 强制执行 Allman 风格）
- `}` 必须单独占一行，并与控制语句的首字母对齐。
- `do...while` 结构中，`while` 前的 `}` 可以单独占一行，`while (...);` 写在下一行，且 `while` 对齐 `do` 的首字母。（clang-format 默认如此）

### 1.7 一行一条语句或标号 `[agent]`

- 每行最多写一条程序语句或一个 `case` 标号。（clang-format 禁止将控制块压缩到一行，但不能拆分同一行内的多条独立语句，需 agent 保证）

### 1.8 一次只声明/定义一个变量或常量 `[agent]`

- 一条声明或定义语句只能引入一个变量或常量。

### 1.9 指针和引用声明风格 `[clang-format]`

- 声明指针或引用时，`*` 和 `&` 必须紧挨类型名书写，例如 `char* s;`，不得靠近变量名。

### 1.10 长语句换行 `[clang-format]`

- 任何长度超过 80 字符（含缩进）的语句必须换行（列宽限制由 clang-format 自动检测）。
- 换行在低优先级操作符处进行，操作符放置在新行的行首（clang-format 已配置 `BreakBeforeBinaryOperators: All`）。
- 新行缩进 4 个空格。如果语句因优先级层次多或嵌套过深导致过长，应先拆分为多个简单语句（拆分逻辑由 agent 审查）。

### 1.11 表达式必须使用括号 `[agent]`

- 对于包含二元或三元操作符的表达式，必须使用括号明确标出运算顺序，直至表达式的最高级逻辑，不得依赖操作符默认优先级。

## 2. 注释

### 2.1 文件注释 `[agent]`

- 每个头文件（`.hpp`）和实现文件（`.cpp`）的首部必须包含以下格式的文件注释：

  ```C++

  //-----------------------------------------------------------------------------
  //【文件名】
  //【功能模块和目的】
  //【开发者及日期】QJQ 2026.7.29（改为当前日期）
  //-----------------------------------------------------------------------------

  ```

### 2.2 类注释 `[agent]`

- 每个类的声明之前必须包含以下格式的注释：

  ```C++

  //-----------------------------------------------------------------------------
  //【类名】
  //【功能】
  //【接口说明】
  //【开发者及日期】QJQ 2026.7.29（改为当前日期）
  //-----------------------------------------------------------------------------

  ```

### 2.3 函数注释 `[agent]`

- 函数声明前必须包含精炼注释，让使用者快速了解函数用途。
- 函数定义前必须包含以下格式的详细注释：

  ```C++

  //-----------------------------------------------------------------------------
  //【函数名称】
  //【函数功能】
  //【参数】（必须标明每个参数是输入参数还是输出参数）
  //【返回值】（必须解释返回值的意义）
  //【开发者及日期】QJQ 2026.7.29（改为当前日期）
  //-----------------------------------------------------------------------------

  ```

### 2.4 空循环体注释 `[agent]`

- 任何空循环体内部必须添加确认性注释（如 `//空循环`），以表明这是有意为之。

### 2.5 多个 case 共用出口注释 `[agent]`

- 若多个 `case` 标签共用同一代码块和出口，必须在出口处（如 `break` 前）添加注释，说明共用的意图。

### 2.6 必须注释的位置 `[agent]`

- 以下位置必须包含注释说明意图：
  - 变量声明或定义（解释变量的意义、存取关系等）
  - 数据结构声明（解释其用途）
  - 分支语句（解释各分支条件含义）
  - 函数调用（解释调用目的）
  - 非显而易见的赋值（说明赋值的意义）
  - 较长程序块的结束处（标识结束，如 `} // if (x == 0) 结束`）

### 2.7 行末注释对齐 `[clang-format]`

- 同一函数或模块内的行末注释，其起始列必须对齐（由 clang-format 自动完成）。

## 3. 命名

### 3.1 标识符命名规范 `[agent]`

- **变量**：变量名 = 作用域前缀 + 类型前缀 + 物理意义。
  - 物理意义部分必须由至少一个英文单词构成，各单词首字母大写，其余字母小写（约定俗成的缩写如 ID 可全大写）。
  - 作用域前缀规则：
    - 全局变量：`g_`（指针为 `g_p`）
    - 类的私有/受保护成员或文件作用域变量：`m_`（指针为 `m_p`）
    - 静态局部变量：`s_`
    - 非静态局部变量、函数形参、类的公有成员：无前缀
  - 类型前缀规则（指针前缀 `p` 优先级最高；`unsigned` 前缀 `u` 次之；具体类型前缀第三）：
    - `char` -> `c`，`int` -> `i`，`short` -> `n`，`long` -> `l`，`long long` -> `ll`，`float` -> `f`，`double` -> `r`
    - 无符号整型仅 `unsigned int` 时用 `u` 替换 `i`，其余组合叠加。
    - 非简单类型（结构体、类、枚举等）无类型前缀；引用无类型前缀。
    - 公有数据成员、局部变量、形参无类型前缀。
- **常量**：名字必须全部大写（包括 `const`、`constexpr` 修饰的量和枚举值）。
- **宏**：所有宏名必须全部大写。
- **自定义类型**：类、结构体、枚举、联合体、`typedef`、`using` 别名、命名空间的名字必须以大写字母打头。
- **函数**：函数名必须以大写字母打头，由动词性单词或动宾短语构成，各单词首字母大写。
- **布尔相关**：返回 `bool` 类型的变量或函数名必须以 `Is` 或 `Has` 等开头。
- **禁止事项**：
  - 禁止使用以下划线 `_` 或双下划线 `__` 开头的标识符。
  - 禁止使用仅靠大小写区分的名称。
  - 命名必须具有明确物理含义，见名知义。

### 3.2 标识符长度 `[agent]`

- 标识符长度必须在 4 到 25 个字符之间（下限不计作用域和类型前缀，上限包含全名）。
- 允许使用广泛认同的缩写（如 `Idx`、`Btn`、`Sln`）。
- `for` 循环计数器或迭代器变量可使用 `i`、`j`、`k` 等简单字符，不受长度限制。

### 3.3 文件命名 `[agent]`

- 每个代码文件（`.hpp` / `.cpp`）的命名必须与其中声明或定义的最主要函数、类或整体功能保持一致。

## 4. 语句与表达式

### 4.1 一条语句一个赋值操作符 `[agent]`

- 一条程序语句中最多只能包含一个赋值操作符（`=`, `+=`, `-=`, `*=`, `/=`, `%=`, `>>=`, `<<=`, `&=`, `|=`, `^=`, `++`, `--`）。

### 4.2 控制条件中禁止赋值 `[agent]`

- `if`, `while`, `for`, `switch` 的条件表达式中禁止使用任何赋值操作符。必须将赋值操作移到控制语句之前单独完成。

### 4.3 禁止左值重复出现 `[agent]`

- 在一个表达式中，一个左值最多只能被赋值一次，且最多只能出现一次。禁止出现 `i = t[i++]`、`a = b = c + a` 等语句。

### 4.4 禁用 goto `[agent]`

- 禁止使用 `goto` 语句。

### 4.5 浮点数比较 `[agent]`

- 禁止对浮点类型（`float`、`double` 等）使用 `==` 或 `!=` 进行精确比较。必须改用范围比较（`>`, `<`, `>=`, `<=` 等）。

### 4.6 switch 语句 `[agent]`

- 每个 `case` 分支必须以 `break` 结尾（连续的空 `case` 可共用一个 `break`）。
- 必须包含 `default` 分支处理意外情况，除非 `case` 已穷举被判定表达式的全部可能取值。

### 4.7 指针的初始化与释放 `[agent]`

- 定义指针变量或常量时必须立刻初始化。若无法赋予有效值，必须初始化为 `nullptr`。
- 用 `delete` 或 `delete[]` 释放指针所指内存后，必须将该指针赋值为 `nullptr`（除非该指针本身紧接着即将销毁）。

### 4.8 new 与 delete 配对 `[agent]`

- `new` 必须与 `delete` 一一对应，`new[]` 必须与 `delete[]` 一一对应，并在同一逻辑层次内成对出现。

### 4.9 显式布尔表达式 `[agent]`

- 控制语句的条件表达式必须使用显式布尔比较。例如必须写成 `if (test == true)` 而非 `if (test)`，写成 `while (isRunning == true)` 而非 `while (isRunning)`。严禁使用 `while (1)` 这样的简写。

### 4.10 函数实参禁止赋值操作 `[agent]`

- 函数调用的实参列表中禁止使用赋值操作符（包括 `++`、`--`）。所有副作用必须在函数调用之前单独完成。

## 5. 函数

### 5.1 函数体长度 `[agent]`

- 函数体（不计注释行）不得超过 100 行。

### 5.2 参数名称 `[agent]`

- 函数声明和定义中，必须为每个参数指定名称，禁止省略参数名（如 `void f(int, char*);` 不允许）。

### 5.3 返回值类型 `[agent]`

- 除构造函数外，每个函数必须明确指定返回值类型。若无返回值，必须写明 `void`。

### 5.4 消除重复代码 `[agent]`

- 任何出现两次及以上的相同或高度相似的代码逻辑，必须提取为独立的函数，并在原处调用该函数。

---

## 6. 程序组织

### 6.1 头文件内容限制 `[agent]`

- 一个头文件只允许包含对一个函数、一类功能相近的函数或一个类的声明（模板和内联函数的声明与实现可在同一头文件内，但必须声明在前、实现在后，且不可使用定义性声明）。

### 6.2 源文件内容限制 `[agent]`

- 一个源文件只允许包含对一个函数、一类功能相近的函数或一个类的实现。

### 6.3 声明与定义分离 `[agent]`

- 头文件中只能包含声明，不得包含全局变量或函数的定义（模板、内联函数、宏、`const` 常量可依情况处理）。
- 源文件中只能包含定义，不得放置任何声明（宏和 `const` 可依情况处理）；所有公开声明必须位于对应的头文件中。

### 6.4 只允许包含头文件 `[agent]`

- 只允许通过 `#include` 包含头文件（`.hpp`），禁止包含源文件（`.cpp`）或其他任何文件。

### 6.5 防止重复包含 `[agent]`

- 每个头文件必须使用包含守卫防止重复包含，格式为：

  ```cpp
  #ifndef HEADER_NAME_HPP
  #define HEADER_NAME_HPP
  // 文件内容
  #endif
  ```

  标识字符串必须唯一，建议使用文件的大写名称。

## 7. 全局变量（公共变量）

### 7.1 严格限制使用 `[agent]`

- 除非有充分理由并在注释中明确说明，否则禁止定义全局变量。应优先使用函数参数、返回值或类数据成员共享数据。

### 7.2 必须明确定义 `[agent]`

- 若确实需要全局变量，必须通过注释明确说明该变量的含义、作用、取值范围、与其他变量及操作函数的关系。

### 7.3 禁止与局部变量重名 `[agent]`

- 全局变量（包括任何文件作用域的全局可见变量）不得与任何局部变量或函数参数重名。

---

## 8. 类

### 8.1 显式默认构造函数 `[agent]`

- 必须为每一个类显式定义默认构造函数，除非该类在语义上不应该存在默认构造函数（可使用 `using` 继承基类构造函数）。

### 8.2 显式拷贝构造函数 `[agent]`

- 必须为每一个类显式定义拷贝构造函数，除非该类在语义上不应该被拷贝。

### 8.3 显式赋值运算符 `[agent]`

- 必须为每一个类显式重载 `operator=`，除非该类在语义上不应该被拷贝。

### 8.4 显式析构函数 `[agent]`

- 必须为每一个类显式定义析构函数。

### 8.5 基类虚析构函数 `[agent]`

- 基类的析构函数必须声明为 `virtual`。

### 8.6 不重新定义非虚函数 `[agent]`

- 在派生类中禁止重新定义基类中的非虚函数。如需不同行为，必须在基类中将该函数声明为虚函数。

### 8.7 new/delete 重载配对 `[agent]`

- 若类重载了 `operator new`，必须同时重载 `operator delete`。

### 8.8 禁止公有数据成员 `[agent]`

- 类中禁止定义 `public` 数据成员，除非该成员为常引用型且没有任何读写规则（即纯只读常量引用，可以公开）。

### 8.9 声明与实现分离 `[agent]`

- 类的声明必须放在 `.hpp` 文件中，实现放在 `.cpp` 文件中。
- 内嵌类的声明在外部类的 `.hpp` 中，实现在外部类的 `.cpp` 中。
- 类模板和内联函数的声明和实现即使同在 `.hpp` 文件中，也必须严格分离：先声明，后实现，禁止使用定义性声明。

### 8.10 继承层数限制 `[agent]`

- 类的继承层数不得超过 5 层。若确实需要超过 5 层，必须在类注释中给出特别理由。

### 8.11 多继承限制 `[agent]`

- 禁止使用多继承，除非经过严格评审确认不可避免且无更优替代方案（如组合或接口）。使用多继承时必须在注释中阐明理由，并采取明确措施避免菱形继承等问题。

---

## 9. 其它

### 9.1 用 const 常量代替无参数宏 `[agent]`

- 对于常量定义，必须使用 `const` 或 `constexpr`，禁止使用 `#define` 定义无参数宏常量。

### 9.2 用内联函数代替有参数宏 `[agent]`

- 对于带参数的宏，必须使用 `inline` 函数替代，禁止使用有参数宏。

### 9.3 C++ 风格类型转换 `[agent]`

- 所有类型转换必须使用 C++ 风格的类型转换操作符（`static_cast`、`dynamic_cast`、`const_cast`、`reinterpret_cast`）。禁止使用 C 风格强制转换（如 `(int)x`）。

### 9.4 删除无用代码 `[agent]`

- 所有不再使用的代码（包括被注释掉的旧代码）必须从正式代码库中彻底删除，不允许保留。
