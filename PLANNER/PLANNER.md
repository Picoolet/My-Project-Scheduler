# 业务层（Service 层）功能需求规格说明

> 本部分依据《2025面向对象程序设计训练》大作业**第 2 章”软件基本功能要求”** 及 **第 3.5 条（MVC 模式中的 Service 层职责）** 整理。  
> **业务层定位**：与界面实现耦合，可以认为是”没有界面的整个软件功能集合”。本部分仅陈述业务层**必须实现的功能需求**（即 Service 层需向上层（界面层）提供的服务契约），不涉及具体类设计、方法签名或架构实现细节。

## 1. 项目模型导入

- **功能目标**：根据给定的文件名，将以特定格式编码存储的项目调度模型文件导入到内存中，转化为可编辑、可执行调度计算的可重用类对象。
- **格式支持**：必须至少支持 **PPM 格式**（格式规范参见附录 1）。
- **扩展性考量（架构约束）**：从支持多种模型格式的角度出发，导入机制的设计应具备扩展性（需考虑**导入器（Importer）类的继承体系**），不能仅为本次作业的 PPM 格式单独编写专用逻辑，应便于未来兼容其他格式（如微软 Project XML、Primavera P6 XER 等）。

## 2. 项目模型导出

- **功能目标**：将内存中的项目模型对象，根据给定的文件名，以特定格式编码写入项目文件。
- **格式支持**：必须至少支持 **PPM 格式**。
- **扩展性考量（架构约束）**：与导入同理，导出机制的设计应具备扩展性（需考虑**导出器（Exporter）类的继承体系**），便于未来输出多种文件格式。

## 3. 人工项目模型修改

业务层需提供对当前内存中项目模型的手工编辑能力，具体分解如下。

### 3.1 任务（Task）管理

- **3.1.1 列出所有任务**：按容器索引顺序显示所有 Task 对象，展示其**序号、名称、工期、前置任务列表和后继任务列表**。显示格式由界面层决定，业务层负责提供完整数据。
- **3.1.2 删除指定任务**：通过容器索引定位并删除指定 Task。删除时，必须**同时删除**与此 Task 相关联的**所有 Dependency**（无论该任务是作为前置还是后置），且该任务占用的**资源引用关系自动解除**。
- **3.1.3 添加新任务**：通过给定的**名称**和**工期**向项目中添加一个 Task。
  - 名称不可与已有任务重复。
  - 若工期为 **0**，则自动创建为里程碑任务（MilestoneTask）；否则创建为普通任务（BasicTask）。
- **3.1.4 查询指定任务的前驱和后继**：列出指定 Task（通过容器索引）的**所有后继任务（Successors）** 和**前驱任务（Predecessors）**，显示其容器索引和名称。
- **3.1.5 修改指定任务**：修改指定 Task（通过容器索引）的**名称**或**工期**。
  - 若修改后工期变为 **0**，任务类型自动转为里程碑任务（MilestoneTask）。
  - 若修改后工期大于 **0**，任务类型自动转为普通任务（BasicTask）。
  - **约束**：修改前后，任务在容器中的**索引保持不变**。

### 3.2 依赖（Dependency）管理

- **3.2.1 列出所有依赖**：显示每个 Dependency 对象的**序号、前置任务的容器索引、后置任务的容器索引以及依赖类型（Type）**。
- **3.2.2 删除指定依赖**：根据**容器索引**或**前/后置任务信息**删除指定的依赖关系。
- **3.2.3 添加新依赖**：通过给定的**前置任务、后置任务、依赖类型（FS/SS/FF/SF）和 Lag**，向项目中添加一个非重复的 Dependency。
  - **唯一性约束**：不能存在两对前置、后置任务完全相同的依赖。
  - **DAG 约束**：添加后必须保证整个项目依赖图**不产生循环依赖环**（即必须保持有向无环图 DAG 性质），违反时操作应被拒绝。

### 3.3 资源（Resource）管理

- **3.3.1 列出所有资源**：显示每个 Resource 对象的**容器索引、名称、单位成本**。
- **3.3.2 添加新资源**：通过给定的**名称**和**单位成本**添加一个 Resource。名称不可重复。
- **3.3.3 为任务分配资源**：通过**任务序号**和**资源序号**，为指定 Task 分配一个 Resource。
  - 一个 Task 可分配**多个** Resource。
  - 一个 Resource 可被**多个** Task 同时使用（资源共享，不限定资源总数）。

## 4. 统计信息显示

- **功能目标**：向界面层提供当前项目模型的宏观统计指标。
- **必须包含的数据**：
  - **Task 总数**（含普通任务与里程碑任务）。
  - **Dependency 总数**。
  - **Resource 总数**。
  - **当前项目的总工期**（即关键路径长度，单位为天）。

## 5. 项目模型验证与调度计算

### 5.1 合理性验证（IsValid）

业务层需提供项目模型合理性校验接口，**同时满足**以下全部条件时判定项目合理（返回 True），否则应返回具体错误信息：

- **① 依赖图无环**：整个依赖图必须为严格有向无环图（DAG）。
- **② 无悬挂节点**：所有 Task 均位于至少一条**从某起始节点到某终止节点的路径**上（即不存在孤立或不可达的悬挂节点）。
- **③ 引用完整性**：所有 Dependency 中引用的**前置任务**和**后置任务**均真实存在于当前任务列表中。

### 5.2 关键路径调度计算（Inference）

在项目具有合理性（IsValid == True）的前提下，业务层需执行关键路径法（CPM）计算，并返回以下结果：

- **默认规则**：所有无前置依赖的任务（入度为 0）的**最早开始时间（ES）** 设定为第 **0** 天。
- **前向传播**：通过逐层前向传播，计算每个 Task 的**最早开始时间（ES）** 和**最早完成时间（EF）**。
- **后向传播**：从终止任务反向传播，计算每个 Task 的**最晚开始时间（LS）** 和**最晚完成时间（LF）**。
- **输出结果**（供界面层展示）：
  1. 项目的**总工期**（即所有任务中最大的 EF 值）。
  2. 位于**关键路径上的所有任务 ID 列表**（按拓扑顺序排列）。判定准则：凡满足 **EF == LF** 或 **ES == LS** 的任务，即为关键路径上的任务。

## 补充说明（针对业务层的架构约束）

- 业务层（Service 层）**不直接依赖**任何 GUI 特定数据类型（如 `QString`），仅面向标准 C++ 类型进行数据传递。
- 业务层对象在整个程序生命周期中**只能产生 1 个对象实例**（即采用单例模式约束）。
- 业务层不得包含用户交互代码（如 `cout/cin` 或弹窗），所有输入参数由界面层传入，所有计算结果通过返回值或引用参数回传，由界面层负责呈现。

## 整个项目的简化类图

Project (纯数据载体)
 ├─ vector<Task>               (Task 内部组合 IAllocationPolicy)
 ├─ vector<Dependency>         (Dependency 存前后置 TaskId)
 ├─ vector<Resource>
 ├─ vector<ResourceAllocation>
 └─ 内部邻接索引 (predecessors_, successors_)

Task
 ├─ id, name, duration
 └─ unique_ptr<IAllocationPolicy> policy_   // 根据 duration 自动切换

IAllocationPolicy (接口)
 ├─ NormalPolicy   : canAllocate() = true
 └─ MilestonePolicy: canAllocate() = false

ScheduleResult (纯数据)
 └─ 提供 getEarlyStart(id) 等访问器

CPMCalculator
 └─ ScheduleResult calculate(const Project&) const;

ProjectEditor (门面)
 ├─ TaskEditor
 ├─ DependencyEditor
 ├─ ResourceEditor
 └─ 内部调用 Validator / 图更新
